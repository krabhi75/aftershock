---
id: INC-1042
title: Carrier retry marked the same parcel delivered twice
fault_class: retry_blind_write
fixed_symbol: harborline.movement.confirm_delivery
---

On 12 March the west hub received the carrier webhook for parcel HBL-44021 twice, 90 seconds apart, because the first acknowledgement timed out. `confirm_delivery` appended the event a second time, so the parcel showed two delivery scans.

The patch stores `event_id` on `applied_events` and returns immediately when that id is already present. Pickup confirmation, customs release, and exception resolution still assign `status` and append the event with no such check. A retried webhook on those paths will double-apply the same way.
