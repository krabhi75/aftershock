IBM Bob 2.0 · post-incident class closure

Aftershock

The ticket closed one function. The fault class is still open.

The model does not decide what is still broken. A structural scan does. IBM Bob only writes the patch.

1

The failure mode

Search is the expensive part. It should not be a chat.

Asking an agent to find similar bugs spends the context window on the repository. The list can change the next time the question is asked. The coins go to looking, not to closing.

Aftershock fixes the list before the model speaks. The same source returns the same siblings.

2

The design

Three steps. Only one of them is a model.

01

Incident

The note names the function that was fixed, and the fault class. That function is the pattern.

02

Scan

Python AST. Module-level functions in Harborline. Zero Bobcoins. Milliseconds.

03

Bob

Three subagents, one function each, one file each. The parent applies them and runs the tests once.

4

The write fence

Bob is allowed to repair. It is not allowed to search.

Each subagent reads one function and writes closures/<name>.py. It does not edit Harborline. It does not run commands. It does not open the rest of the tree.

Forty Bobcoins close one class. The other siblings stay on the local board, because listing them is free.

5

Leave with this

Close the class, not only the ticket.

Fact first. Fence the agent. Then let it write.

Harborline is fictional. The incidents are original. The scan is local. The closer is IBM Bob.
